# 拍摄方案策划 Skill

给一个模糊拍摄想法 + 日期 + 城市某区 → 补全主题（含剧情）、联网查区级天气、按当天条件动态产出一份人像拍摄方案，md + HTML 双版交付。

核心资产在 `references/` 下三份重文档，**按环节按需读取，不要一次性全读**：
- `condition-adjustments.md` — 条件→调整映射表（天气 × 时段 × 风格），"动态"的根
- `pose-library.md` — 摆姿库（按风格分组，每个姿势标适用光线）；输出时按景别（远全中近特）呈现
- `theme-seeds.md` — 主题种子库（模糊想法→主题完善方向，含剧情示范）

`templates/` 下两份统一模板：
- `plan-template.md` / `plan-template.html` — 7 节结构 + 小红书社区风格样式已固化

**产出方案时基于 templates/ 填充，不要从零重写结构和样式**。本 SKILL.md 只放流程、判断与边界。具体布光/摆姿/主题方向一律从 references 取，不要凭记忆临场编。

## 输入契约

**必给**（缺则追问，不硬凑）：
- 拍摄想法（可模糊）
- 日期（具体哪天）
- 城市某区（给得比区细仍按所在区取天气；给得比区粗要追问到区）

**可选**：
- 拍摄对象（单人/情侣/家庭；缺默认单人）
- 时段意向（缺按天气最优时段定）
- 已有器材（**优先存进 memory，见"设备 memory 机制"；缺则首次问一次后存档**）
- 禁忌

风格/主题**不要**等用户给——这是 skill 第 2 环节要补的。

## 输出原则（重要）

方案要**突出重点**，不是均匀铺开：
- **重点**：主题+剧情、参考图（按远全中近特）
- **极简**：时间、地点、天气数据来源、日出日落推算方法等次要/无关信息——一行带过，不写出处、不写推算过程
- **不重复**：设备若 memory 已覆盖就不列，只补缺口；服装+道具合并小篇幅
- 参考图是方案核心篇幅，无图保留占位框等用户后续补充

## 工作流（6 环节）

### 1. 信息门槛检查
核对必给三项。缺日期/城市区直接追问。想法模糊正常不追问。对象/时段/器材缺了按可选规则处理。

### 2. 主题完善与风格推荐
Read `references/theme-seeds.md`。把用户模糊想法扩展成完整主题概念，输出**五件**：
- **场景叙事**：一句话定调（如"晚高峰退潮后的地铁站台，JK 少女独行的疏离感"）
- **剧情描述**（重点）：一段贴合主题的故事（2-4 句），给拍摄一条情绪弧线/叙事线——开场、推进、收尾的情绪走向，让片子有故事感而非摆拍堆砌。如"她撑伞走过空荡站台，雨停了也没收伞，在出站口的光里停了一下，像是等人，又像只是不想走"
- **情绪基调**：从 疏离/清新/复古/张力/温柔/冷峻 里定一个主情绪
- **视觉关键词**：色系、质感、构图倾向
- **推荐风格**：主推一个 + 1-2 个备选，附一句理由

**风格要和想法强相关**。**推荐风格要结合当天天气**（雨天推情绪疏离比清新合理）——所以这一环节需要先查天气（环节 3），或在天气已查到后再定风格。完成后**把主题五件贴给用户确认或微调**，再往下走。不要跳过确认直接出方案（用户明确授权"直接出方案/不用确认"时可跳过，但方案第 1 节须含完整主题五件作为追溯说明）。

### 3. 联网查天气
用 web-access skill 查"日期 + 城市某区"的：天气状况、云量/晴雨、降水概率、风力、气温、日出日落、AQI（能查到就带）。**查不到区级降级城市级并在方案里一句话标注"天气为城市级，到场先看天"，不写数据来源出处**。查都查不到就问用户，不要编天气。

### 4. 光照时段计算
根据日期 + 城市算日出/黄金/正午/蓝调/日落，地点朝向受限时标注实际可用光时段。**只在内部用于定主拍时段，输出里只给一行"主拍 XX-XX（时段名）"，不出光照时间表、不写推算方法**。

### 5. 条件→调整映射
Read `references/condition-adjustments.md`。把"天气类型 + 当前时段 + 主题风格"三维喂进映射表，产出当天策略：用光方案、机位、摆姿基调、道具、服装色系。

**这是 skill 区别于模板的环节**：同样主题，晴天硬光和多云柔光的摆姿基调、机位、道具必须不同。两份不同天气方案长得一样就是映射没做，要重做。

摆姿从 `pose-library.md` 按当天光线筛适配姿势，但**输出时不按姿势表呈现，按景别（远全中近特）组织参考图**（见环节 6）。

### 6. 产出方案（md + HTML 双版）
两份都写，存到 `shoot-planner/output/` 下：`方案_YYYYMMDD_主题.md` / `.html`。

**基于 `templates/plan-template.md` 和 `templates/plan-template.html` 填充，替换 `{{占位符}}`，不要从零重写结构和 CSS**。HTML 样式已按小红书社区风格固化（见下"HTML 视觉规范"）。

#### md 版结构（8 节，重点在前）
1. **主题 + 剧情描述**（重点）：主题一句话 + 一段贴合主题的剧情故事（2-4 句情绪弧线）。篇幅适中，是方案的叙事锚
2. **当天条件**（极简）：一行——日期 · 城市某区 · 地点（含站点结构特征如"高架三层站"）· 天气一句话 · 主拍时段。不写数据来源、不写日出日落推算方法
3. **参考图 · 远全中近特**（重点，篇幅最大）：按远景/全景/中景/近景/特写五个景别组织参考图。**机位要落到地点具体结构**（如"屏蔽门玻璃反光""石凳坐姿""扶梯仰拍""连廊雨前景"），不要抽象的"找开阔地"。每景别 1-3 张外链参考图，配情绪/动作/光线要点。**无图保留占位框**，等用户后续补。每景别旁附小红书自搜关键词
4. **服装 + 道具**（合并小篇幅）：一个紧凑清单，和主题+天气联动
5. **设备**（memory 驱动）：机身镜头走 memory（已录入富士 XT30II + 35/50/23mm），只写"机身镜头见 memory" + 本次关键补充项（防护/消耗品）+ **本次风格的机内参数**（胶片模拟/白平衡/曝光等，随风格天气变，每次可不同）
6. **天气动态调整建议**：今天这种天气的优势/代价/关键取舍 + 特别提醒（含地点安全如黄线、周边配套、模特保暖等实用项）
7. **Plan B**：固定一个备选场地。复杂场地可阶梯化（雨大→站厅通道，雨更大→站外天桥下）
8. **后期调色建议**（小篇幅）：直出优化参数（LR/Capture One 基础/色彩/质感）+ 备选风格调色。富士机身可注明机内直出接近成片

#### HTML 版要求
HTML 直接基于 `templates/plan-template.html` 填充，结构和 CSS 已固化（小红书社区风格），只替换占位符。参考图按远全中近特 5 个景别卡片；每景别有直链图用 `.ref` 块（可复制多个），无图用 `.ph` 占位框；pose-tags 光线标签 `.l` 类：`.r`=柔光红、`.p`=低光紫、不带类=灰。

## HTML 视觉规范（小红书社区风格，已固化在模板里）

- **主色**：小红书标志红 `#FF2442`，话题标签红底浅红字（`.tag`）、光线标签红底（`.l.r`）
- **卡片**：白底 `#fff`、圆角 14px、轻阴影 `0 2px 12px rgba(0,0,0,.05)`、间距松，模拟笔记信息流
- **顶部笔记头**：圆形渐变头像 + 加粗标题（20px/800）+ 副位置行 + 话题标签行（`#话题` 红胶囊，天气/时段灰胶囊 `#f2f3f5`）
- **参考图 2 列瀑布感**（`.grid2`），图卡圆角、底部渐变蒙层标题（`.cap`）；占位框虚线 + 🖼 图标"待补充"
- **小红书自搜按钮**：红色描边胶囊（`.xhs-btn`）
- **天气调整**：优势/代价双卡片（`.weather-grid`）+ 红色编号 tips
- **Plan B**：红色虚线卡片（`.planb`）
- **emoji 点缀**：🔭远景 🚶全景 👬中景 😌近景 🔍特写 🌂 PlanB
- **底部装饰互动条**：❤️ 收藏 / 📌 待补充 / 🔗 Unsplash
- 零依赖、内联 CSS、单文件，手机浏览器可看，img 加 `alt` 兜底断网

## 设备 memory 机制

用户已有器材是稳定信息，不应每次重复列。

- **首次**用户提到器材（或主动问一次后），用 Write 存进 memory：`shoot-planner-equipment.md`（type: project），记录机身、镜头、补光、脚架、配件等
- 每次产出方案前，先 recall 这份 memory。**对照本次拍摄所需器材**：
  - 所需项 memory 里都有 → 设备节只写"设备清单见 memory，本次无补充"
  - 有缺口（如本次需要透明伞、密封袋而 memory 没有）→ 只列缺口项作为"本次需补充/携带"
- memory 不存在时 → 问用户要设备清单，存档，再继续；当次方案设备节标"待录入 memory，本次暂列关键补充项"

## 核心约束（强制，来自真实失败）

1. **天气是输入不是装饰**。环节 5 映射必须真读天气字段做决策。把天气写进概览但机位摆姿道具和晴天没区别，等于没做动态调整——这是 skill 存在的全部理由，违反即判定不合格回环节 5 重做。
2. **参考图按景别（远全中近特）组织，是方案重点篇幅**。无图的景别保留占位框等用户补充，不要硬塞不匹配的图凑数。
3. **不生图**。参考图一律外链真实摄影作品，不用图像生成模型出人像示意图。
4. **参考图来源诚实**。优先小红书但 AI 搜小红书不稳，实际取图走能稳定抓取的渠道（Unsplash/Pexels/摄影师站），每景别旁附"小红书自搜关键词"引导自行搜。不假装搜到小红书。
5. **摆姿必须和当天光线联动**。参考图景别块下标注适用光线，雨天方案里不出现硬光飘逸姿势。
6. **固定一个 Plan B**。不管当天天气好坏都带一个备选场地，风格延续、能扛坏天气。
7. **输出突出重点**：主题+剧情+参考图是重点；时间地点天气数据来源极简；设备 memory 驱动；服装道具合并小篇幅。违反"均匀铺开"就是没遵守本约束。

## Gotchas（真实坑）

- **跳过主题确认直接出方案**——用户想法模糊时最易犯。环节 2 结束必须停下来贴主题五件（含剧情）让用户确认。
- **剧情描述写成摆姿说明**——剧情是故事情绪弧线，不是"先靠墙再走动再回眸"。剧情给方向，摆姿是执行。
- **天气查不到还硬编**——降级城市级并一句话标注，或问用户，不要靠"估计今天晴天"。
- **参考图不按景别堆**——把所有图一股脑塞，或用不匹配的图凑数。必须按远全中近特分块，无图留占位。
- **设备每次重复列**——用户已有 35mm 镜头还每次推荐一遍。走 memory，只补缺口。
- **时间地点天气数据来源写一大堆**——"临平气象台9/14发布""timeanddate推算±2分钟"这些是无关信息，输出里砍掉，一行带过。
- **机位给万能模板**——"找开阔地、利用引导线"不算机位。要具体到"站台东端漫射光、35mm 横构图、下午走动抓拍"。
- **参考图 alt 兜底**——img 加 alt 描述景别和内容，断网也能知道这块该放什么。
- **小红书关键词太宽**——给"JK"太宽，给"JK 地铁 站台 摆姿"才准。
- **编造 references 里不存在的具体名词**——执行时没真读 references，凭记忆编出"灵动竹影"这类主题名，或把地铁站座椅写成"石凳"（高架站是金属/塑料候车座椅，石凳属公园亭子）。具体名词（设施名/主题名/地点结构）必须从 references 取或核实地物事实，不要临场发明。
